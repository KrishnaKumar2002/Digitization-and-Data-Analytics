About the Exercise

In Distributed Computing III, we will explore the basic concepts of scalability using Apache Spark. To perform computation we will try to estimate value of Pi using Monte Carlo method. During this computation, we will try to understand the how system scales in both directions (scale-up and scale-out).

Exercise 3.1-3.3

In these exercises, we will explore scalability using JupyterNotebooks. These exercise can be performed on local-machine as well as on HPC (if it is available). Pay attention to the comments present in the JupyterNotebook cell. On a local-machine, you will only be able to explore scale-up (increasing the resources of a single machine/node).

Exercise 3.4

In this exercise we will learn about scale-out (more than one node) of spark application on HPC cluster using CLI. Repeat the measurements on Barnard with multiple nodes and discuss the results. For this exercise we will use batch job to perform computation. More information about batch jobs can be found here. This exercise will also be discussed by instructors but students are encouraged to try on their own and present the results in the next exercise.

Exercise Files

The script main.sh submits chained jobs with the last job being submitted for post processing.
spark.sh initializes configuration, starts the cluster and submits the PySpark job (app.py).
post_process.py is used to do the post processing of results
The files are related(or invoked) as follows:
main.sh
    |
    ├─> spark.sh
    │   |
    │   └─> app.py
    │
    └─> post_process.py

Tasks

Scale-up:

Task 1: In app.py,
edit functionToMeasure to add code for calculating computing time for map and reduce functions,
complete code to initialize spark-context and stop the same.
Task 2: In spark.sh,
find a way to add executor cores and parallelism information.
Task 3: In post_process.py
create programming logic to compute speedup,
programming logic to plot parallelism vs processing time and parallelism vs speedup.
Task 4:
Figure out how to run scale-up experiments using main.sh.
Hint: ./main.sh -h
Find the best CPU numbers (parallelism) for the setup. Use this to conduct scale-out experiments below.
Plot the results and explain your outcome.
